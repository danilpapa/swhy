# Руководство по разметке эталонов

Заготовка. Правила разметки пишутся на этапе E1 (эталон истории методов и построчный эталон), дополняются в E9 (пары ObjC → Swift) и E11 (цепочки регрессий). Ниже — только то, что `docs/TZ.md` фиксирует заранее.

## Эталон истории методов (E1)

**Состав** (ТЗ, E1): 50 методов из 5 репозиториев, по 10 из каждого, у каждого не меньше 3 изменяющих коммитов; не меньше 10 с переездом между модулями и не меньше 10 с ObjC-происхождением.

**Разбиение:** 25 методов для подбора порогов, 25 для проверки. Проверочную часть не смотреть до E17 и не использовать для подбора порогов, весов и параметров.

**Кандидаты:** объединение `git log -L`, `git log --follow` и текущей версии инструмента; затем ручная проверка каждого коммита.

**Что размечается для каждого коммита:** изменил ли он метод; класс изменения; коммит появления.

**Классы изменения:**

| Класс | Когда ставится |
| --- | --- |
| `FormatOnly` | заполняется в E1 |
| `RenameOnly` | заполняется в E1 |
| `Refactoring` | заполняется в E1 |
| `Semantic` | заполняется в E1 |
| переезд | заполняется в E1 |

**Решения, принятые заранее** (ТЗ, E1, пункт 5):

- изменение doc-комментария — отдельный технический класс `DocOnly`;
- изменение атрибутов (`@MainActor`, `@objc`) — `SignatureChanged: attributes`;
- merge-коммит сравнивается с каждым родителем.

**Второй разметчик** проверяет 30% методов; считается каппа Коэна.

**Формат файлов:** `eval/oracle/methods/<repo>-<n>.json`. Схема файла — заполняется в E1.
